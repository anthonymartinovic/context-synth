# Context Synth v0.1

## Goal

Prove that LLM-powered extraction from markdown sources produces useful, faithful, well-structured context artifacts. Everything in the roadmap depends on this working well.

## Pipeline

```
Snap → Extract + Rank (single Gemini call) → Assemble → Verify → context.md
```

- **Snap**: Read configured source files, normalize, hash, count tokens.
- **Extract + Rank**: One Gemini Flash call that reads all sources, extracts key information, and ranks it by priority within each section. Combined into a single call for simplicity.
- **Assemble**: Include ranked items within token budgets. Each item is fully included or fully omitted.
- **Verify**: Structural only -- confirms each item's source reference points to a real file and paragraph in the snapshot. Semantic verification comes later.
- **Output**: `context.md` with source tracking metadata.

## CLI Commands

- `cs init` -- generate starter `contextsynth.yml`
- `cs synth` -- run full pipeline, emit `context.md`
- `cs snap` -- diagnostic, show captured sources
- `cs synth --no-llm` -- fallback mode, config-order verbatim assembly

## Configuration

```yaml
version: "1"

output:
  path: context.md

budget: 10000

llm:
  provider: gemini
  model: gemini-2.0-flash
  api_key_env: GEMINI_API_KEY

sections:
  - name: Domain Knowledge
    sources:
      - docs/domain/overview.md
      - docs/domain/glossary.md
    budget: 0.30

  - name: Architecture Decisions
    sources:
      - docs/adrs/*.md
    budget: 0.25

  - name: Requirements
    sources:
      - docs/requirements/*.md
    budget: 0.25

  - name: Constraints
    sources:
      - docs/constraints.md
    budget: 0.20
```

Single `llm` block (not per-stage). One model for the combined extract+rank call.

## Fallback Mode

If `llm` block is omitted or the API key is not set:
- Extract and rank stages are skipped.
- Source file contents are included verbatim in config order.
- Token budgets apply at the file level (whole files included or omitted).
- Source tracking still records everything.

## Source Tracking

Per-section HTML comments listing extracted items with source references and status:

```markdown
## Domain Knowledge
<!-- cs:sources
  - text: "The domain model follows event sourcing patterns"
    source: docs/domain/overview.md
    paragraph: 5
    hash: sha256:a3f2c1...
    status: included
    priority: 1
  - text: "Commands are validated at the aggregate boundary"
    source: docs/domain/overview.md
    paragraph: 12
    hash: sha256:a3f2c1...
    status: omitted (budget exceeded)
    priority: 8
-->
```

## Token Estimation

Word-based approximation: `word_count / 0.75`. No tokenizer dependency.

## What's Not Built

- Separate extract and rank calls (combined in v0.1)
- Semantic verification (structural only)
- Multi-model support (Gemini only)
- Caching (every run calls the LLM)
- Additional providers (Claude, GPT)

## Success Criteria

1. `cs init` generates a usable config file.
2. `cs synth` produces a `context.md` from markdown source documents.
3. Extracted information is meaningful -- not trivial, not hallucinated, not redundant.
4. Each extraction references a real source file and paragraph.
5. Token budgets are respected.
6. Fallback mode works without LLM configuration.
7. Running the tool on real project docs produces a context artifact that an AI agent would benefit from.

## Key Risk

**Extraction quality.** Whether Gemini produces good extractions from arbitrary markdown is empirical. If extraction quality is poor, the product thesis doesn't work. Iterate on the prompt before expanding scope.
