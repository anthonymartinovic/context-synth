# Context Synth v0.3 (Projected)

> **This is a projection, not a finalized plan.** The scope and direction of v0.3 will be shaped by what we learn from v0.1 and v0.2. Expect this document to change.

## Direction

Enable multi-model support so each pipeline stage can use the model best suited for its task. The target configuration:

- **Extract**: Gemini (large context window for ingestion)
- **Rank**: Claude (reasoning and judgment)
- **Verify**: GPT (structured faithfulness checks)

## Likely Changes

- **Per-stage model configuration** in `contextsynth.yml`.
- **Provider abstraction** with implementations for Gemini, Anthropic, and OpenAI.
- **Cross-model verification**: the model checking faithfulness is different from the model that did the extraction.

## Open Questions

- Does multi-model actually produce better results than single-model? Need to measure.
- Is the added complexity (three API keys, three providers, three failure modes) worth it?
- Which specific models within each provider family work best for each stage?
- How do we handle partial provider failures gracefully?
