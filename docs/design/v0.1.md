# Context Synth -- v0.1 Design

## Purpose

First implementation slice. Validates the core thesis from `docs/PROJECT_SPEC.md` with the narrowest possible scope. Written in Go, distributed as a single binary.

## Release Goal

Prove that declared sources with explicit weights can be compiled into a bounded, traceable, reviewable context artifact where weight visibly shapes the output.

## Scope

### Included

- Single Go binary: `cs`
- Local markdown files as the only source type
- Per-source weight declaration
- User-defined section structure with budget allocation
- Global token budget
- Deterministic source capture with provenance and content hashing
- Bounded artifact generation with recorded omissions
- Deterministic fallback mode when no LLM is configured
- Optional LLM-backed extraction, ranking, and verification
- Single global LLM configuration

### Excluded

- MCP-backed ingestion
- Non-markdown source types
- Per-section LLM configuration
- Caching or incremental regeneration
- CI integration, artifact diffing, drift detection
- Stable artifact format commitment

## CLI

| Command | Purpose |
|---------|---------|
| `cs init` | Generate starter `contextsynth.yml` |
| `cs snap` | Resolve sources, report the snapshot |
| `cs synth` | Run the pipeline, write the artifact |

`cs synth` flags: `--config`, `--output`, `--verbose`, `--dry-run`, `--no-llm`

## Configuration

```yaml
version: "1"

output:
  path: Contextfile

budget: 10000

sources:
  - path: docs/domain/overview.md
    weight: 1.0
  - path: docs/domain/glossary.md
    weight: 0.8
  - path: docs/adrs/*.md
    weight: 0.7
  - path: docs/constraints.md
    weight: 0.6

sections:
  - name: Domain Knowledge
    budget: 0.30
  - name: Architecture Decisions
    budget: 0.25
  - name: Requirements
    budget: 0.25
  - name: Constraints
    budget: 0.20

llm:
  provider: gemini
  model: gemini-2.5-pro
  api_key_env: GEMINI_API_KEY
```

- `sources` are declared at the top level with explicit per-source weight (0.0–1.0).
- `sections` define output structure and budget allocation. They do not own sources.
- Classification of source material into sections is the Extract stage's job.
- `llm` is optional. When absent, the pipeline runs in deterministic fallback mode.
- Source paths are relative to the config file. Globs are supported.
- Section budgets are proportional weights normalized at runtime.

## Pipeline

**Snap** — Resolve configured paths and globs. Read local markdown. Normalize into source-type-agnostic snapshots with content hashes, provenance references, and token estimates. Deterministic.

**Extract** — LLM-backed. Decompose snapshot content into discrete items. Classify each item into user-provided sections. Each item inherits its source's weight and provenance. Non-deterministic.

**Rank** — Order items within each section by weight descending. Equal-weight ties broken by source declaration order. Deterministic.

**Assemble** — Fill sections within budget. Higher-weight items included first. Omissions recorded with reason. Deterministic.

**Verify** — Produce a reviewable surface: what was included, what was omitted, source basis for each included item. Not a pass/fail gate.

## Fallback Mode

When `--no-llm` is set or no LLM is configured:

- Extract, Rank, and Verify are skipped
- Source contents assembled in weight order within budget
- Provenance, boundedness, and omission recording still hold

## Artifact

The output must:

- Be markdown
- Respect the declared budget
- Preserve section structure from config
- Include per-item source references (file path, content hash)
- Include artifact metadata: generator version, snapshot identity, config identity, token usage, operating mode
- Record omitted items with reason

## Verification Surface

Must answer:

- What source produced each included item?
- What was omitted and why?
- What snapshot was used?
- What weight did each source carry?

## Acceptance Criteria

1. Two sources with different weights produce output where higher-weight material takes precedence.
2. Artifact never exceeds configured budget.
3. Every included item traces to a specific source file and content hash.
4. Omitted items are recorded with reason.
5. `cs synth --no-llm` produces a governed artifact preserving boundedness, provenance, and weight ordering.
6. Source/snapshot layer is behind an interface clean enough that a future MCP adapter would not require pipeline changes.
7. `cs snap` makes the source set inspectable before synthesis.

## Deferred

- Stable source-reference model (paragraph/span granularity)
- Stable artifact format
- Per-section LLM configuration
- Multi-source verification semantics
- Incremental regeneration and caching
- MCP ingestion
