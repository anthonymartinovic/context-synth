# Context Synth -- v0.1 Design

## Purpose

First implementation slice. Validates the core thesis from `docs/PROJECT_SPEC.md` with the narrowest possible scope. Written in Go, distributed as a single binary.

## Release Goal

Prove that declared sources with explicit weights can be compiled into a bounded, traceable, reviewable context artifact where weight visibly shapes the output.

## Scope

### Included

- Single Go binary: `cs`
- Local markdown files as the only source type
- Per-source weight declaration
- User-defined section structure with budget allocation
- Global token budget
- Deterministic source capture with provenance and content hashing (SHA-256)
- Bounded artifact generation with recorded omissions
- Deterministic fallback mode when no LLM is configured
- Optional LLM-backed extraction, ranking, and verification
- Single global LLM configuration

### Excluded

- MCP-backed ingestion
- Non-markdown source types
- Per-section LLM configuration
- Caching or incremental regeneration
- CI integration, artifact diffing, drift detection
- Stable artifact format commitment

## CLI

Built with Cobra. Three subcommands:

| Command | Purpose |
|---------|---------|
| `cs init` | Generate starter `contextsynth.yml` |
| `cs snap` | Resolve sources, report the snapshot to stdout |
| `cs synth` | Run the pipeline, write the artifact |

`cs synth` flags: `--config`, `--output`, `--verbose`, `--dry-run`, `--no-llm`

Default config path: `contextsynth.yml` in the current directory when `--config` is not specified.

### `cs snap` Output

Prints a human-readable table to stdout:

```

docs/domain/overview.md     1.00    2,340   a1b2c3d4
docs/domain/glossary.md     0.80      890   e5f6a7b8
```

## Configuration

```yaml
version: "1"

output:
  path: Contextfile

budget: 10000

sources:
  - path: docs/domain/overview.md
    weight: 1.0
  - path: docs/domain/glossary.md
    weight: 0.8
  - path: docs/adrs/*.md
    weight: 0.7
  - path: docs/constraints.md
    weight: 0.6

sections:
  - name: Domain Knowledge
    budget: 0.30
  - name: Architecture Decisions
    budget: 0.25
  - name: Requirements
    budget: 0.25
  - name: Constraints
    budget: 0.20

llm:
  provider: gemini
  model: gemini-2.5-pro
  api_key_env: GEMINI_API_KEY
```

- `sources` are declared at the top level with explicit per-source weight (0.0–1.0).
- `sections` define output structure and budget allocation. They do not own sources.
- Classification of source material into sections is the Extract stage's job.
- `llm` is optional. When absent, the pipeline runs in deterministic fallback mode.
- Source paths are relative to the config file. Globs are supported.
- Section budgets are proportional weights normalized at runtime.

## Pipeline

**Snap** — Resolve configured paths and globs. Read local markdown. Normalize into source-type-agnostic snapshots with SHA-256 content hashes, provenance references, and token estimates. Deterministic.

**Extract** — LLM-backed. Decompose snapshot content into discrete items. Classify each item into user-provided sections. Each item inherits its source's weight and provenance. Non-deterministic. If the same knowledge exists in multiple sources, each source produces its own extractions independently — no deduplication.

**Rank** — Order items within each section by weight descending. Equal-weight ties broken by source declaration order. Deterministic.

**Assemble** — Fill sections within budget. Higher-weight items included first. Omissions recorded with reason. Deterministic.

**Verify** — The verification surface is the artifact itself. The front matter provides snapshot identity and operating mode. Inline source annotations answer what source produced each item and its weight. The omissions appendix records what was excluded and why. Not a pass/fail gate.

## Fallback Mode

When `--no-llm` is set or no LLM is configured:

- Extract, Rank, and Verify are skipped
- Source contents assembled as a flat weight-ordered document within budget
- Section structure from config is not applied (no classification without an LLM)
- Provenance, boundedness, and omission recording still hold

## Token Estimation

Budget enforcement uses a word-count heuristic: `tokens = ceil(words * 1.33)`. The same estimator is used at snap time and assembly time so budget accounting is internally consistent. The estimator is behind a single function so a model-specific tokenizer can replace it later.

## Source References

Source traceability in v0.1 operates at file level. Each extraction traces to:

- Source file path (relative to config)
- SHA-256 content hash of the full file at snapshot time
- Source weight
- Declaration order in config

Sub-file addressing (paragraph, span, byte range) is deferred.

## Artifact

The output is a markdown file (default: `Contextfile`). Its structure:

**YAML front matter** — machine-readable metadata:

```yaml
---
generator: cs v0.1.0
mode: deterministic | full
snapshot: <sha256 of concatenated source hashes>
config: <sha256 of config file>
timestamp: 2026-03-08T12:00:00Z
budget: 10000
tokens_used: 8742
---
```

**Sections** — one H1 per section from config, in declaration order. Content appears under its classified section. Each item is followed by a blockquote source annotation:

```markdown
# Domain Knowledge

The platform handles products, orders, customers, and inventory as a single
source of truth for small-to-medium e-commerce merchants.

> source: docs/domain/overview.md | weight: 1.0 | hash: a1b2c3
```

**Omissions appendix** — a system-generated `# Omissions` section at the end:

```markdown
# Omissions

| Source | Reason | Weight | Tokens |
|--------|--------|--------|--------|
| docs/constraints.md | exceeded budget | 0.6 | 1200 |
```

The artifact format is explicitly unstable in v0.1. It is a working format, not a contract.

## Acceptance Criteria

1. Two sources with different weights produce output where higher-weight material takes precedence.
2. Artifact never exceeds configured budget.
3. Every included item traces to a specific source file and content hash.
4. Omitted items are recorded with reason.
5. `cs synth --no-llm` produces a governed artifact preserving boundedness, provenance, and weight ordering.
6. Source/snapshot layer is behind an interface clean enough that a future MCP adapter would not require pipeline changes.
7. `cs snap` makes the source set inspectable before synthesis.

## Deferred

- Stable source-reference model (paragraph/span granularity)
- Stable artifact format
- Per-section LLM configuration
- Multi-source verification semantics (deduplication, cross-source items)
- Incremental regeneration and caching
- MCP ingestion
