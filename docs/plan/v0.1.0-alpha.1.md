# Context Synth -- v0.1 Implementation Plan

## Overview

This plan breaks the v0.1 build into six milestones ordered by dependency and risk. The critical path is M1–M3: after M3, the tool is usable and the core thesis is provable. M4–M6 add convenience, LLM support, and polish.

The build target is a single Go binary (`cs`) that compiles local markdown sources into a bounded, traceable context artifact. Design decisions are recorded in `docs/design/v0.1.md`.

### Key Design Choices

- `internal/` keeps all packages unexported. The only public surface is the CLI.
- `source/` defines a `Provider` interface so future adapters (MCP, etc.) slot in without touching the pipeline. Satisfies acceptance criterion 6.
- `extract/` has two implementations behind the same interface: `llm.go` for full synthesis, `passthrough.go` for deterministic fallback. The pipeline receives the right extractor — it does not branch on mode.
- `pipeline/pipeline.go` orchestrates stages in order. The CLI calls this.

### Source Provider Interface

```go
type Provider interface {
    Resolve(ctx context.Context, decl config.SourceDecl) ([]ResolvedSource, error)
}

type ResolvedSource struct {
    Path        string
    Content     []byte
    ContentHash string   // SHA-256
    TokenCount  int
    Weight      float64
    DeclOrder   int      // position in config sources list
}
```

A future MCP adapter implements `Provider` with a different `Resolve`. The pipeline never changes.

## Milestones

### M1: Scaffold + Config + Model

**Goal:** `go build` succeeds. Config loads and validates. Domain types exist.

| Work Item | Package | Notes |
|-----------|---------|-------|
| `go mod init` | root | |
| Core domain types | `model/` | `Source`, `SnapshotItem`, `Extraction`, `SynthPlan`, `Artifact`, `Omission` |
| Config types | `config/` | `Config`, `SourceDecl`, `SectionDecl`, `LLMConfig` |
| YAML loader + validation | `config/` | Version check, weight bounds (0.0–1.0), section budget normalization, path resolution |
| Stub `main.go` | `cmd/cs/` | Cobra root command, `--config` flag |
| Token estimator | `token/` | `Estimate(text string) int` — `ceil(words * 1.33)` |

**Tests:** Config loads valid YAML. Rejects missing sources, out-of-range weights, missing budget. Token estimator returns sane values.

---

### M2: Snap + `cs snap`

**Goal:** `cs snap --config contextsynth.yml` resolves sources and prints the snapshot table to stdout.

| Work Item | Package | Notes |
|-----------|---------|-------|
| `Provider` interface | `source/` | `Resolve(ctx, decl) ([]ResolvedSource, error)` |
| Markdown adapter | `source/` | Glob expansion, file read, SHA-256 hash, token estimate per file |
| Snapshot builder | `snapshot/` | Takes resolved sources, produces `[]SnapshotItem` with provenance |
| `cs snap` command | `cmd/cs/` | Load config → resolve sources → print snapshot table |

**Tests:** Glob resolves correctly (single file, wildcard, nested). Missing file errors cleanly. Hash is stable for same content. Snapshot output is deterministic.

**Validates:** Acceptance criterion 7.

---

### M3: Deterministic Fallback Path

**Goal:** `cs synth --no-llm` produces a bounded, traceable artifact from local markdown.

This is the critical milestone. It proves the core thesis without any LLM dependency.

| Work Item | Package | Notes |
|-----------|---------|-------|
| Passthrough extractor | `extract/` | One extraction per source. Content = full source text. No section classification. Weight and provenance inherited. |
| Ranker | `rank/` | Sort extractions by weight desc. Tiebreak: source declaration order. |
| Assembler | `assemble/` | Iterate ranked items. Include items until total budget exhausted. Record omissions with reason. |
| Renderer | `render/` | Write markdown: YAML front matter (version, mode, snapshot hash, config hash, timestamp, token usage), content with blockquote source annotations, omissions table. |
| Verification surface | `verify/` | In deterministic mode: compute included/omitted lists with source, weight, reason. Data consumed by the renderer. |
| Pipeline orchestrator | `pipeline/` | `Run(cfg Config) (Artifact, error)` — snap → extract → rank → assemble → verify. |
| `cs synth` command | `cmd/cs/` | Flags: `--config`, `--output`, `--no-llm`, `--dry-run`, `--verbose`. |

**Tests:**
- Two sources, different weights → higher-weight content appears first (AC 1).
- Total output tokens never exceed budget (AC 2).
- Every item has source path + content hash (AC 3).
- Omitted items recorded with reason (AC 4).
- `--no-llm` produces a complete artifact (AC 5).
- End-to-end test using `testdata/` fixtures.

**Validates:** Acceptance criteria 1–5.

**Note on fallback mode:** Section structure from config is not applied. The output is a flat weight-ordered document. Section assignment requires the LLM-backed Extract stage.

---

### M4: `cs init`

**Goal:** `cs init` generates a starter `contextsynth.yml` in the current directory.

| Work Item | Package | Notes |
|-----------|---------|-------|
| Template generation | inline in CLI | Writes a commented YAML file with placeholder sources, sections, budget |
| `cs init` command | `cmd/cs/` | Refuse to overwrite existing config. Print path on success. |

**Tests:** File is created. Valid YAML. Won't overwrite.

---

### M5: LLM-Backed Pipeline

**Goal:** `cs synth` (without `--no-llm`) uses an LLM to extract, classify, and verify.

| Work Item | Package | Notes |
|-----------|---------|-------|
| LLM client interface | `llm/` | `type Client interface { Complete(ctx, prompt, systemPrompt) (string, error) }` |
| Gemini implementation | `llm/` | Uses the Gemini API. Reads API key from env var specified in config. |
| LLM extractor | `extract/` | Sends snapshot content + section definitions to LLM. Parses response into `[]Extraction` with section classification. Each extraction inherits source weight + provenance. |
| Full assembly with sections | `assemble/` | Per-section budget allocation: `section.budget * total_budget` tokens per section. Include items by section in weight order. |
| Full verification | `verify/` | Compute verification data with section-level detail. |
| Updated renderer | `render/` | Render with H1 per section from config. |
| Pipeline mode selection | `pipeline/` | If LLM config present and `--no-llm` not set → use LLM extractor + section assembly. Otherwise → passthrough + flat assembly. |

**Tests:** Mock LLM client. Verify extractions are classified into correct sections. Verify weight inheritance. Verify per-section budgets are respected. Integration test with real API (gated behind env var).

---

### M6: Polish + End-to-End Validation

**Goal:** Run against example sources. Validate all 7 acceptance criteria. Clean up.

| Work Item | Notes |
|-----------|-------|
| Create a real `contextsynth.yml` using the example sources | 3 example docs with different weights |
| Run `cs snap`, `cs synth --no-llm`, `cs synth` | Verify output against acceptance criteria |
| Error handling audit | Missing files, bad YAML, LLM failures, empty sources |
| CLI help text and `--verbose` output | User-facing polish |
| README update | Installation, usage, examples |

## Build Order Summary

```
M1  Scaffold + Config + Model          ← can build, can't run
M2  Snap + cs snap                     ← first runnable command (AC 7)
M3  Deterministic fallback path        ← core thesis proved (AC 1–5)
M4  cs init                            ← onboarding convenience
M5  LLM-backed pipeline               ← full synthesis mode
M6  Polish + end-to-end               ← all 7 ACs validated
```

M1–M3 is the critical path. After M3, the tool is usable and proves the thesis. M4 is small. M5 is where LLM complexity lives, isolated behind an interface. M6 is validation.

## Acceptance Criteria Mapping

| AC | Description | Milestone |
|----|-------------|-----------|
| 1 | Higher-weight material takes precedence | M3 |
| 2 | Artifact never exceeds budget | M3 |
