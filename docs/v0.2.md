# Context Synth v0.2 (Projected)

> **This is a projection, not a finalized plan.** The scope and direction of v0.2 will be shaped by what we learn from building and using v0.1. Expect this document to change.

## Direction

Split the combined extract+rank call into separate pipeline stages. Add LLM-powered semantic verification. Add caching so repeated runs don't call the LLM unnecessarily.

## Likely Changes

- **Separate extract and rank stages** for independent iteration and caching.
- **Semantic verification**: an LLM reads each extracted item alongside its source paragraph and judges whether it's faithful.
- **Caching layer**: extraction and ranking results cached by content hash, skipping LLM calls when sources haven't changed.

## Open Questions

- Does splitting extract and rank actually improve quality, or is the combined call good enough?
- What verification failure rate do we see in practice? Is semantic verification worth the cost?
- How should cache invalidation work when config changes but sources don't?
- Should verification use the same model or a different one? (Multi-model comes in v0.3, but maybe earlier if needed.)
